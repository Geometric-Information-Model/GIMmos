# gim-tools reference: fleet

Per-group verb reference for the gim-tools skill.
Generated by `gim-verbs --gen-refs`; deterministic, do not hand-edit.

## gim-preflight

Signature: `gim-preflight --repo <name|path> [--repo <name|path>]... [--branch <name>] [--skip-gh-auth] [--skip-jira-auth] [--dry-run] [--json]`

Fleet preflight: auth status, per-repo branch/clean state, parallel fetch, conditional ff-only pull, and product docs indexes.

| Flag | Detail |
| --- | --- |
| `--repo <name\|path>` | Repository name or path (repeatable). An absolute path is used as given, a relative path resolves against the current repo root, and a simple name resolves case-insensitively under the parent of the current repo root (must be a git root, .git file or directory). Missing names list the available directories; case-only ambiguity lists the matches. Records branch plus clean/dirty; untracked .agent-scratch/ evidence is ignored by the dirty check. |
| `--branch <name>` | Expected branch (default: dev). Pulls --ff-only only when clean and on this branch; pass the prefs default_dev_branch explicitly. |
| `--skip-gh-auth` | Skip gh auth. The docs index then marks each family ok=false with next=null (open-PR source unavailable); the run itself does not fail. |
| `--skip-jira-auth` | Skip acli jira auth; marks the check skipped, not failed. |
| `--dry-run` | Run no fetch or pull; report the planned actions plus the read-only status/docs index. |
| `--json` | Emit { ok, dry_run, gh_auth, jira_auth, repos[] } with per-repo fetch/pull status and docs_indexes. |

## gim-pr

Signature: `gim-pr --repo <name|path> (--files-file [<path>] | --file <path> [--file <path>]...) --message <subject> --title <title> --target <branch> [--new-branch <branch>] [--pr-body <path>] [--draft] [--delete-pr-body] [--remote <name>] [--assignee <login>] [--dry-run] [--json]`

One explicit PR flow: stage the declared file list, guard the index, commit, push -u, create the PR, then run the stack lifecycle. First-PR mode refuses dev, main, and release/* as protected branches. Lifecycle mechanics (config, init/add/link/sync verification, result fields, manual fallback) are owned by github-cli-workflow section 4 + references/gim-stack-lifecycle.md; this verb is the executable path.

| Flag | Detail |
| --- | --- |
| `--repo <name\|path>` | Repository name or path. An absolute path is used as given, a relative path resolves against the current repo root, and a simple name resolves case-insensitively under the parent of the current repo root (must be a git root). |
| `--files-file [<path>]` | File list source. With no value, derives .agent-scratch/pr-files/<feature>/<step>/files.txt from the head branch (--new-branch when given, else the current branch): known first-PR prefixes (feature, docs, chore, hotfix, release, fix, bugfix, refactor, test, ci, build, perf) map <prefix>/<slug> to <slug>/<prefix>; other <feature>/<step> branches map to <feature>/<step>. More than one slash is rejected. |
| `--file <path>` | Repo-relative file path; repeatable. Exactly one file source (--files-file or --file) is required. |
| `--message <subject>` | Required. Commit subject (git commit --message). |
| `--title <title>` | Required. PR title. |
| `--target <branch>` | Required. PR base branch (the previous step branch, or the feature branch for the first PR). |
| `--new-branch <branch>` | Step PR: create and check out this branch inside the local stack (gh stack add) before staging. Omit for the first PR, which adopts the current branch with gh stack init. |
| `--pr-body <path>` | PR body file. A relative path resolves against the repo root, then must resolve inside the evidence directory (same directory as files.txt/result.json); an absolute path must already be inside it. Required unless --draft; a draft without a body passes --body "". |
| `--draft` | Create the PR as a draft. |
| `--delete-pr-body` | Delete the PR body file after success. The file is kept on failure. |
| `--remote <name>` | Push/stack remote (default origin). git push -u <remote> HEAD; gh stack link and sync get --remote. |
| `--assignee <login>` | PR assignee (default @me). |
| `--dry-run` | Resolve the repo/branch/file list and print the command plan in execution order (config, init/add, stage, commit, push, PR create, link, view, sync); no mutation. |
| `--json` | Emit the result record (also written to result.json): repo, branch, head, new_branch, remote, files, commit, push, pr, stack (method, number, url, pending, verified, link {exit,output}, sync {exit,output,count_line}, view_error, error), body, warnings, error. |

## gim-jira-search

Signature: `gim-jira-search [--keyword <kw>...] [--jql <jql>] [--project <key>] [--limit <n>] [--current-sprint] [--json]`

Read-only Jira search: no input queries the project (default GIM); keyword queries use summary OR description containment, one query per keyword; explicit JQL is used as given. Dedupe by issue key; return key, summary, status, and assignee display name only (never email, account id, or avatar). --current-sprint resolves the single active sprint from the D0 board; zero or many active sprints fail and require an explicit sprint filter in --jql. Default --limit is 50.

| Flag | Detail |
| --- | --- |
| `--keyword <kw>` | Optional keyword query; repeatable. Builds project = <key> AND (summary ~ "<kw>" OR description ~ "<kw>"), one acli query per keyword. Omit with --jql and no-input project scans. |
| `--jql <jql>` | Optional explicit JQL query; used as given. No input means project = <key>. |
| `--project <key>` | Project key for keyword and no-input queries (default GIM). |
| `--limit <n>` | Maximum results per acli query (positive integer; default 50). |
| `--current-sprint` | Resolve the active sprint with acli board list-sprints and AND sprint = <id>; fail when zero or many active sprints exist. |
| `--json` | Emit { ok, count, truncated, items[] }; each item is { key, summary, status, assignee } with assignee display name only. |

## gim-jira-create

Signature: `gim-jira-create --summary <s> [--project <key>] [--type <type>] [--assignee <@me|email>] [--unassigned] [--description-file <f>] [--sprint <id>] [--current-sprint] [--parent <key>] [--label <l>...] [--dry-run] [--json]`

Create a Jira work item from the observed acli template, then assign and verify. Payload assignee is null; assigns @me/explicit unless --unassigned. Description text becomes plain ADF paragraphs split on blank lines (markdown not interpreted); labels default null and a label-specific rejection retries once with null; sprint is the D0 bare integer under sprint.field_id. Returns key + URL, never email/account id. --dry-run prints payload and commands without calling acli.

| Flag | Detail |
| --- | --- |
| `--summary <s>` | Required work-item title. |
| `--project <key>` | Project key (default GIM). |
| `--type <type>` | Work-item type (default Task). |
| `--assignee <@me\|email>` | Assignment target (default @me). Conflicting with --unassigned. |
| `--unassigned` | Skip post-create assignment (explicit exception). |
| `--description-file <f>` | Markdown file converted to the observed ADF document. |
| `--sprint <id>` | Explicit sprint id; D0 config must support create-time sprint assignment. |
| `--current-sprint` | Resolve the single active sprint from the D0 board; zero/many fails and requires explicit --sprint. |
| `--parent <key>` | Parent work-item key (sub-task). |
| `--label <l>` | Label; repeatable. Defaults to null; a label rejection retries once with null. |
| `--dry-run` | Print payload and exact create/assign/view commands; no acli call. |
| `--json` | Emit { ok, dry_run, key, url, project, type, summary, sprint_id, assigned, payload, commands, warnings, error } for success, dry-run, and argument failures; never email/account id. |

## gim-jira-transition

Signature: `gim-jira-transition --key <key> --to <status> [--project <key>] [--dry-run] [--json]`

Transition a Jira work item to a configured status. Reads the current status with the positional-key view form; a target equal to current is a no-op. Selects routes[].sequence from the D0 jira-transitions.json config and runs each step with acli workitem transition --status (the CLI has no --to flag). Stops at the first failure and returns the exact command and per-step results. --dry-run makes no acli call and prints the placeholder current status, direct target sequence, and command.

| Flag | Detail |
| --- | --- |
| `--key <key>` | Required work-item key such as GIM-123; must belong to the selected project. |
| `--to <status>` | Required target status; validated against the D0 config statuses. |
| `--project <key>` | Project key used for key validation (default: the D0 config project). |
| `--dry-run` | Print current placeholder, target, sequence, and exact command; no acli call. |
| `--json` | Emit { ok, dry_run, key, project, current, target, sequence, commands, results, error } for success, no-op, dry-run, and argument failures. |

## gim-wrapup-gather

Signature: `gim-wrapup-gather --repo <name|path> (--chain <pr> | --pr <n>... | --branch <branch>...) [--out <path>] [--parallel <n>] [--log-parallel <n>] [--json]`

Fetch-only PR gather for gim-wrapup. PowerShell shim + dependency-free Node helper (Node >= 20). --chain is primary: walk head/base down then up from one PR, bottom -> top, stopping on trunk, ambiguity, cycle, or 50 PRs. --pr/--branch are explicit fallbacks; modes are mutually exclusive. Independent PR/log pools (defaults 4/2); threads map reviews[].comments[] with replies[]. Failing-check gh run view logs stream to logs/ (50 MB/file, 200 MB total, gather-dir-relative log_file, log_source job/run). Writes schema v1 gather.json (1-space, nulls omitted, pass/skipping checks reduced to {name,state}) plus the authored responses.json shell (PRs with unresolved threads or top-level comments, plus per-PR comment strings) under .agent-scratch/wrapup/<slug>/ or --out. Never posts, resolves, pushes, or calls gh api.

| Flag | Detail |
| --- | --- |
| `--repo <name\|path>` | Repository name (case-insensitive sibling) or path; resolved through Resolve-GimFleetRepo. |
| `--chain <pr>` | Primary mode: walk the open-PR stack around this PR. Mutually exclusive with --pr and --branch. |
| `--pr <n>` | Explicit PR number; repeatable. Mutually exclusive with --chain and --branch. |
| `--branch <branch>` | Explicit PR head branch; repeatable. Mutually exclusive with --chain and --pr. |
| `--out <path>` | Output path for gather.json, repo-relative or absolute inside the resolved repo. Default .agent-scratch/wrapup/<slug>/gather.json; responses.json is its sibling. |
| `--parallel <n>` | PR fetch concurrency (default 4). Independent of --log-parallel. |
| `--log-parallel <n>` | Failing-log fetch concurrency (default 2). Independent of --parallel. |
| `--json` | Emit { ok, path, repo, summary, warnings, error } only; read the file for the normalized document. |

## gim-wrapup-respond

Signature: `gim-wrapup-respond --repo <name|path> --file <responses.json> --harness <name> [--dry-run] [--json]`

Consume responses.json: inline thread replies via gh-pr-review comments reply (then threads resolve only when resolve=true and remotely open), free-form per-PR comments via gh pr comment in order. Apply-time read-only remote refresh per touched PR; sibling <responses>.result.json receipt records posted_at/resolved_at/remote_state/last_error; reruns skip completed entries and retry failures. Authored responses.json is never rewritten; --dry-run makes zero gh calls; footer appended once; per-entry failures return ok=false with counts.

| Flag | Detail |
| --- | --- |
| `--repo <name\|path>` | Repository name or path for gh -R; resolves through Resolve-GimFleetRepo. |
| `--file <path>` | Existing responses.json under a workspace root from roots.json; relative paths resolve against the resolved repo root. |
| `--harness <name>` | Required footer harness name: letters, digits, dot, underscore, hyphen. |
| `--dry-run` | Print planned replies/resolves/comments; no gh call and no receipt write. |
| `--json` | Emit { ok, repo, file, receipt, dry_run, posted, resolved, skipped, failed, warnings[], actions[], error }; ok=false when any entry failed. |
