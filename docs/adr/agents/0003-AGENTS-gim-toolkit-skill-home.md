# gim-* toolkit home: agent skill layout in GIMmos

The `gim-*` PowerShell command toolkit (19 fixed-name, data-only verbs) lives in GIMmos as an agent skill at `.agents/skills/gim-tools/`, not at the `tools/GIMTools/` location originally specified in the design document. Layout: `SKILL.md` (frontmatter `name: gim-tools` matching the directory per the agentskills.io spec; body carries the verb list + canonical pipelines, ≤500 lines), `scripts/` (the `GIMTools.psd1/.psm1` module, `roots.json`, `private/` helpers, `verbs/` one file per verb), `references/` (per-group flag details + recommended harness-config recipe), `tests/` (Pester 6 — **optional dependency**, only needed to run the suite; see `docs/guides/0001-setup-powershell-7.md`). GIMmos is the single host; other workspace repos consume from this checkout. The skill directory is not agent-writable: the deny-write protection (invariant: the toolkit is the one place a single approved write converts every allowlisted verb into arbitrary execution) applies to `.agents/skills/gim-tools/**` and is documented for the user to wire into harness config later — this build ships no harness config changes. Scripts remain PowerShell 5.1-compatible (portable — they run unchanged on pwsh 7), **with one exception: containment-critical reparse-point resolution (`Get-GimRealPath` in `private/GimPaths.ps1`) requires the .NET Core `FileSystemInfo.Target` API and therefore pwsh 7+**; the repo runtime standard is **pwsh 7** (setup guide 0001), which is what the harness and the test suite use, so the containment guarantee holds in practice and PS 5.1 is a best-effort compatibility tier for data-only verb code; `gim` is not an approved PowerShell verb, so the module exports commands as-is and is imported with `-DisableNameChecking`.

**Status:** accepted. *Amended (Z2): scoped the PS 5.1 compatibility claim — reparse-point containment requires pwsh 7+; PS 5.1 is best-effort for data-only code only.*

## Considered Options

- **`tools/GIMTools/` per original design** — rejected; the design itself notes these are agent tooling, not CAD-domain tools, and a user-facing `tools/` home implied a domain fit the toolkit does not have.
- **Agent skill at `.agents/skills/gim-tools/`** (chosen) — matches repo convention (all skills under `.agents/skills/`), satisfies the agentskills.io spec (name matches directory, sanctioned `scripts/`/`references/` dirs, SKILL.md ≤500 lines with progressive disclosure into `references/`), keeps one copy in the workspace hub.
- **`tools/` + separate skill copy** — rejected; two copies of the implementation is the stale-copy failure mode the design explicitly warns against.
- **Per-verb loose `.ps1` files** — rejected; a module gives one import point, one deny path, and free `Get-Help` from comment-based help.
