# gim-run / gim-probe execution confinement

`gim-run <build|test|run|publish|ef|format>` and `gim-probe` are the execution tier: they run agent-requested commands on the developer machine, so they carry the strongest internal controls. Every invocation resolves `--project` (or the implicit cwd) to an absolute path and asserts containment under the **current repo plus `.agent-scratch/`** (exec roots — narrower than the read roots list; sibling workspace repos stay read-roots only, so execution can never escape the consuming checkout); `$env:TEMP`, UNC paths, and junction/symlink escapes are rejected explicitly, with Windows path canonicalization tested adversarially. Write and execution verbs confine to the current repo plus `.agent-scratch/`; `gim-apply` alone also admits a validated OS temp root, while `gim-write`, `gim-fix`, `gim-run`, and `gim-probe` remain repo-only (scratch work stays visible and inside path policy rather than an arbitrary `$TEMP`). Execution uses an argv array (no shell interpolation of agent text), a hard timeout with kill, environment scrubbing of credential variables (`NUGET_API_KEY`, `GH_TOKEN`, Azure/AWS vars) before exec, and an append-only audit log of every invocation (resolved path, verb, args). Publishing (`dotnet nuget push`), supply-chain changes (`dotnet nuget add source`, `dotnet new install`, workload installs), and `git push` are deny-listed and documented in `references/harness-config.md` — applied by the user later, not by this build.

**Status:** accepted. *Amended (A7): exec roots narrowed from the roots.json list (incl. sibling repos) to current repo + `.agent-scratch/` only; sibling repos are read roots only. `--` trailing-args sentinel: the PowerShell binder consumes the first `--` before the verb sees it, so colliding trailing tokens require `-- -- <args>`; documented in gim-run help.* *Amended (A3): `gim-apply` may target the OS temp root under a safety floor (rooted local path, not a drive root or UNC, at least two segments deep, and not equal to or an ancestor of the user profile, local app data, app data, Windows directory, system root, or the repo root); all other write and execution verbs stay repo-only.*

## Considered Options

- **Wrapper verb with roots confinement (chosen)** — a raw allowlisted `dotnet build` cannot express "only inside these repos"; the wrapper can, and policy lives in the toolkit rather than in each harness config.
- **Raw allowlist of `dotnet build`/`test`** — rejected; MSBuild `Exec` tasks, pre/post-build events, and test bodies are agent-authored code; allowlisting the verb allowlists arbitrary execution.
- **Deny execution outright** — rejected; build/test/run is the normal agent loop, and gim-probe reduces the agent's reason to author throwaway scratch projects.
